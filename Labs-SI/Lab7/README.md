# Lab7. Сжатие записи ДНК (сдвиги и поразрядные операции)

## Задание

```
РАБОТА #3. Использование операций сдвига и поразрядных логических операций.

Преобразование кода ДНК в сжатый вид.

Входной файл в этом каталоге содержит ASCII-запись последовательности азотистых 
оснований в молекуле ДНК 13-й хромосомы гена человека. Предполагается, что эта 
последовательность отвечает за наследственные признаки человека.
В каждой строке по 70 остатков, обозначенными буквами A, G, C, T или N, -
(аденин, гуанин, цитозин, тимин) и последний символ N- неопределенный тип. Для
сжатия записи каждый символ нужно заменить 3-х битной последовательностью. На входе 
символы A, G, C, T, N с кодами 0101, 0107, 0103, 0124 и 0116 (восьмеричные числа).
Также в конце строки встречается символ перехода на новую строку с кодом 012.
Последняя строка может быть неполной (иметь менее 70 символов).
Прочитать файл, упаковать заново без символов 012 в данной последовательности

и записать в файл в двоичном виде как множество чисел типа long long int.
 Установить соответствия значение триады битов азотистому основанию так:
 (0 0 0) =  N;
 (0 0 1) =  A;
 (0 1 0) =  C;
 (1 0 0) =  G;
 (1 1 1) =  T.
Программа также должна подсчитать количество каждого из азотистых оснований и вывести
эти значения в десятичном виде.
Предусмотреть возможность использования других файлов для сжатия (у человека 23 хромосомы)
с передачей имени файла через параметр командной строки argv[1].
Для 4-х типов азотистых оснований хватило бы 2-х битов, но вот N мешает... Попытайтесь
найти алгоритм, в котором сжатие использует 2-х битовую кодировку.
```

## Сборка и запуск

```bash
gcc -Wall -Wextra -std=c99 -O2 main.c -o dna
./dna hs_alt_HuRef_chr13.fa              # создаёт .dna3 и .dna2, печатает статистику
./dna -d hs_alt_HuRef_chr13.fa.dna3 out.txt   # распаковка для проверки
./dna sample.txt                          # небольшой пример
```

## Решение

- Имя файла - через `argv[1]`, можно сжимать любую хромосому. Заголовки (`>...`, `Chromosome 01`) пропускаются, строчные буквы приводятся к прописным, символы `\n` (012) не упаковываются.
- 3-битные коды N=000, A=001, C=010, G=100, T=111; 21 основание в одном `long long` (63 бита). Упаковка - сдвиг влево и `|`, распаковка - сдвиг вправо и маска `& 07`.
- Количество каждого основания выводится в десятичном виде.
- Дополнительное задание (2 бита): A=00, C=01, G=10, T=11, 32 основания в `long long`, а символы N хранятся отдельно списком участков (позиция, длина) - в геноме они идут длинными сплошными блоками. Файл получается ~25% от исходного.
- Режим `-d` восстанавливает текст; проверено, что распакованный файл совпадает с исходным.
